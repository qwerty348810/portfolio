ZenAir App

Коммерческие предложения и управление монтажом

Приложение, которое связывает подбор оборудования, предложение заказчику и монтажную заявку. Отдельные интерфейсы для менеджера, монтажника, диспетчера и администратора работают через общий API.

01 / Задача

Связать продажу оборудования и выполнение работ

После подбора техники нужно рассчитать монтаж, подготовить предложение заказчику и передать данные исполнителю. Я разработал приложение для этих связанных задач: от выбора оборудования до изменения статуса монтажной заявки.

Проектировал структуру данных, разрабатывал пользовательские интерфейсы и API, синхронизацию каталога и автоматизированные проверки.

  1. Оборудование и работы
  2. Предложение заказчику
  3. Назначение монтажника
  4. Выполнение заявки

02 / Работа менеджера

Предложение с оборудованием, работами и условиями

Менеджер выбирает оборудование по бренду, серии и модели, добавляет монтажные работы, условия и данные заказчика. Предложение сохраняется в истории, доступно для экспорта в PDF/PNG и просмотра заказчиком по ссылке без регистрации.

Заказчик может принять предложение по ссылке; менеджер видит его статус. Для выданного КП сохраняются состав оборудования, цены и условия, чтобы документ можно было повторно открыть после изменения текущего каталога.

Связь с WooCommerce

Каталог приложения синхронизируется с магазином. Оборудование используется в конструкторе коммерческих предложений.

Сохранённое предложение

История использует данные выданного документа. Обновление каталога не должно менять его состав и цены.

03 / Выполнение работ

Каждому сотруднику — свой интерфейс

Из сохранённого КП менеджер создаёт монтажную заявку и назначает исполнителя. Монтажник видит свои заявки и данные по работам, а диспетчер — общую доску. Изменения статусов проходят проверку на сервере.

Интерфейс Задачи
Менеджер Подготовка КП, история, работа с заказчиками и назначение монтажника.
Монтажник Назначенные заявки, адрес и детали работ, статусы выполнения и фото.
Диспетчер Общая доска заявок и наблюдение за их состоянием.
Администратор Организации, сотрудники, справочники, аналитика и журнал действий.

04 / Технические решения

Общий API и явные правила работы с данными

Общие контракты

Типы и схемы Zod вынесены в общий пакет. Интерфейсы и сервер используют согласованную структуру данных.

Ролевой доступ

Проверки на сервере учитывают роль сотрудника и организацию. Доступ не ограничивается видимостью кнопок в интерфейсе.

Переходы статусов

Для заявки заданы допустимые переходы: назначена → в пути → на месте → завершена. Предусмотрена отмена.

Один сервер для интерфейсов

Несколько клиентских приложений работают через общий Express API и одну схему данных Prisma.

05 / Автоматизация тестирования

Проверки API, компонентов и пользовательского пути

В проекте есть тесты серверных обработчиков, схем данных, компонентов и браузерных сценариев. Для разных уровней используются Vitest, Supertest, Testing Library и Playwright.

Уровень Примеры проверок
API Авторизация, доступ к данным, создание КП и обработка монтажных заявок.
Компоненты Формы и состояния интерфейсов, взаимодействие с элементами управления.
Браузер Вход → выбор модели → монтажные работы → данные заказчика → скачивание PNG.
Негативный сценарий Печать предложения блокируется, если не заполнены обязательные данные заказчика.

В браузерном сценарии менеджера API подменяется тестовыми ответами: проверка проходит без создания реальных клиентских записей. В этом же сценарии проверяется отсутствие горизонтального переполнения на мобильном размере экрана.

Этот сценарий проверяет пользовательский поток с тестовыми ответами API. Для оценки взаимодействия с реальной базой нужны отдельные интеграционные проверки.

06 / Результат

Связанные инструменты для продажи и монтажа

Реализованы конструктор предложений, история, интерфейс заказчика и работа с монтажными заявками. Проект показывает разработку бизнес-логики, нескольких интерфейсов и проверок на разных уровнях приложения.
